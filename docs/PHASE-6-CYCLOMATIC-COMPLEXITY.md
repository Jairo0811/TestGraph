# Phase 6 — Cyclomatic Complexity

## Goal

Phase 6 adds deterministic cyclomatic-complexity analysis over the Control Flow Graph generated by TestGraph.

The calculation is performed from graph structure, not from source-code text heuristics.

## Pipeline

```text
TGPL Source
    ↓
Lexer
    ↓
Parser
    ↓
AST
    ↓
Control Flow Graph
    ↓
CyclomaticComplexityAnalyzer
    ↓
V(G) + structural metrics
```

## Formulations

For the connected structured CFGs produced by TestGraph, the educational formulations are:

```text
V(G) = E - N + 2
V(G) = P + 1
V(G) = R
```

Where:

- `E` = number of edges;
- `N` = number of nodes;
- `P` = predicate/decision nodes;
- `R` = regions.

The implementation generalizes the graph formula to weakly connected components:

```text
V(G) = E - N + 2C
```

where `C` is the number of connected components. TestGraph-generated program CFGs normally have `C = 1`.

Because TGPL decisions are binary, the generalized predicate formulation used internally is:

```text
V(G) = P + C
```

## Result model

`CyclomaticComplexityResult` exposes:

- node count;
- edge count;
- predicate node count;
- connected-component count;
- edge/node complexity;
- predicate complexity;
- region count;
- formula agreement;
- educational complexity level.

## Educational levels

The UI/API may display the following heuristic guidance:

| V(G) | Level |
|---:|---|
| 1–5 | Low |
| 6–10 | Moderate |
| 11–20 | High |
| 21+ | VeryHigh |

These bands are guidance for learning and prioritization, not an absolute software-quality judgment.

## Academic validation

The original ISO-300 document reports six predicate nodes and `V(G)=7` for Scholarship Calculator. However, the preserved executable flow contains seven binary decision nodes: one age decision plus three GPA decisions in each age branch.

```text
P = 7
V(G) = P + 1 = 8
```

TestGraph preserves the academic value as historical context, but the deterministic CFG analyzer returns `8` for the executable TGPL sample.

## API

Phase 6 introduces:

```http
POST /api/analysis/complexity
Content-Type: application/json
```

Example request:

```json
{
  "sourceCode": "Si edad > 18 Entonces\n    Escribir edad\nFin Si"
}
```

The response includes the complexity value, node/edge/predicate/region counts, all three formula results and their consistency status.

Invalid TGPL returns lexical/parser diagnostics instead of a complexity result.
